рассматриваем исходную таблицу `bundle_flat`, содержащую bundle_id, bundle_name, product_id, category_name, qty, price_rule_code, price_rule_name

Существуют четыре функциональные зависимости. bundle → name,rule; product → category; rule_code → rule_name; (bundle,product) → qty

По `bundle_id` можно определить название комплекта и код ценового правила. По `product_id` определяется категория товара. По коду правила определяется его название. По сочетанию комплекта и товара его количество. Потенциальным ключом является пара `(bundle_id, product_id)`.

Частичные зависимости: название комплекта и код ценового правила зависят только от `bundle_id`, а категория товара — только от `product_id`, 

Транзитивная зависимость: bundle_id → price_rule_code → price_rule_name

Аномалия INSERT заключается в том, что нельзя добавить новое ценовое правило отдельно от комплекта и товара, если их идентификаторы обязательны.
Аномалия UPDATE возникает, когда одно название правила повторяется в нескольких строках и при изменении нужно обновлять все его повторения.
Аномалия DELETE возникает, когда удаление последнего товара из комплекта одновременно приводит к потере информации о самом комплекте.

Изначально таблица находится в 1НФ. Для перехода ко 2НФ устранены частичные зависимости. По зависимости `product_id → category_name` выделена таблица `products`, по зависимости `bundle_id → bundle_name, price_rule_code` выделена таблица `bundles_temp`. Отдельно создана таблица `bundle_items`, содержащая идентификаторы комплекта и товара + его количество.

Для перехода к 3НФ устранена транзитивная зависимость `price_rule_code → price_rule_name`. Таблица `bundles_temp` разделена на две: `bundles`, содержащую идентификатор комплекта, название и код правила, и `price_rules`, содержащую код и название правила.
